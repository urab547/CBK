# 答辩演示手册

老师的要求：演示数据多准备几份——目录结构复杂的 vs 简单的、GB 级的 vs 很小的、
有特殊文件的（要演示特殊文件的处理结果）。这个目录里的东西就是为此准备的：

| 文件 | 作用 |
|---|---|
| `make_demo_data.ps1` | 一键生成 5 组演示数据到 `D:\CBK-Demo` |
| `compare_trees.ps1` | 还原之后，把源目录和还原目录逐项对比，打 √ / × |
| `CbkDemoNative.cs` | 上面两个脚本共用的 Win32 辅助代码（长路径、链接、哈希、权限），不用单独运行 |

**不需要任何 IDE**（不用 PyCharm、不用 VS Code），只要一个管理员 PowerShell。

---

## 一、答辩前准备（提前一天做完）

1. 开始菜单搜 **PowerShell** → 右键 → **以管理员身份运行**。
   （符号链接、属主这两项需要管理员，不是管理员会被跳过。）

2. 进入仓库，确认程序已经编译过：

   ```powershell
   cd D:\CODE\CourseProjects\CompreExper
   .\code\build\msvc\bin\Release\cbk.exe info
   ```

   能输出一行 JSON 就行。没有的话先编译：
   `cd code; cmake --preset msvc; cmake --build --preset release; cd ..`

3. 生成演示数据（约 15 秒，D 盘要留 4 GB 以上空间）：

   ```powershell
   .\scripts\demo\make_demo_data.ps1
   ```

   最后会列出 5 组数据的条目数和大小。**确认最后没有黄色的"注意"**——
   有的话通常是没用管理员运行。

4. 从同一个管理员 PowerShell 启动界面：

   ```powershell
   python gui\gui.py
   ```

5. 按下面第二节完整彩排一遍。彩排完清掉备份和还原结果（演示数据不动）：

   ```powershell
   .\scripts\demo\make_demo_data.ps1 -CleanRestore
   ```

## 二、演示流程（5 分钟）

每一组都是同一个套路：**GUI 备份 → GUI 还原 → 跑对比脚本看 √**。
备份包统一放 `D:\CBK-Demo\backup\`，还原目标统一是 `D:\CBK-Demo\restore\<同名目录>`，
对比脚本靠编号自动找到这两个目录。

| 顺序 | 数据 | 时间 | 要点 |
|---|---|---|---|
| 1 | `02-复杂` | 约 1 分钟 | 基础备份还原：2077 个条目、30 层嵌套、382 字符长路径、emoji/日文文件名、空目录空文件 |
| 2 | `03-大文件` | 约 40 秒 | GB 级：1 GB 备份约 5 秒，内存占用不随文件变大 |
| 3 | `04-特殊文件` | 约 1.5 分钟 | 符号链接、junction、硬链接 |
| 4 | `05-元数据` | 约 1.5 分钟 | 时间戳（100 纳秒）、属性位、权限、属主 |
| 备选 | `01-简单` | 30 秒 | 时间紧时用它代替 02 讲最基本的流程 |

### 1. 复杂目录：`02-复杂`

- **备份页**：源目录选 `D:\CBK-Demo\src\02-复杂`，输出选 `D:\CBK-Demo\backup\02-复杂.cbk`。
  可以选一个压缩算法（如 lz77）顺便展示压缩：10 MB 能压到 3 MB 左右，不到 1 秒。
- **恢复页**：选刚才的备份，目标目录 `D:\CBK-Demo\restore\02-复杂`。
- 对比：

  ```powershell
  .\scripts\demo\compare_trees.ps1 02
  ```

  条目多，只显示统计和不一致项，最后一行应是 **结论：全部一致 √**。
  想让老师看具体条目就加 `-ShowAll`。

可以讲的：路径加 `\\?\` 前缀绕过 260 字符限制；遍历用显式栈不用递归；中文名在内存里是 UTF-16、写进包里是 UTF-8。

### 2. GB 级大文件：`03-大文件`

- 备份时**压缩选"不压缩"**。实测：不压缩备份 4.5 秒、还原 2.2 秒。
  （大文件是随机数据，本来就压缩不动：huffman 约 7 秒、lz77 约 33 秒，压完大小基本不变。）
- 还原后 `.\scripts\demo\compare_trees.ps1 03`，会算 1 GB 文件的 SHA-256 并比对。

可以讲的：全程 64 KB 一块流式处理，不会把整个文件读进内存；所有大小、偏移都是 64 位整数，支持 4 GB 以上的文件。

### 3. 特殊文件：`04-特殊文件`

先让老师看源目录里有什么（`<SYMLINK>`、`<SYMLINKD>`、`<JUNCTION>` 后面方括号里是目标）：

```powershell
cmd /c dir /AL "D:\CBK-Demo\src\04-特殊文件"
fsutil hardlink list "D:\CBK-Demo\src\04-特殊文件\硬链接\三个名字-A.txt"
```

| 名字 | 是什么 |
|---|---|
| `链接-相对路径.txt` | 文件符号链接，目标是相对路径 `目标\真文件.txt` |
| `链接-绝对路径.txt` | 文件符号链接，目标是绝对路径 |
| `链接-目录` | 目录符号链接 |
| `链接-悬空.txt` | 指向一个不存在的文件的符号链接 |
| `联接-junction` | 目录联接 |
| `硬链接\原件.txt` + `别名.txt` | 两个名字共享一份数据 |
| `硬链接\三个名字-A/B.txt` + `另一个目录\三个名字-C.txt` | 三个名字共享一份数据，跨目录 |
| `说明-管道与设备文件.txt` | 为什么没有管道文件（见下） |

备份、还原后：

```powershell
.\scripts\demo\compare_trees.ps1 04
cmd /c dir /AL "D:\CBK-Demo\restore\04-特殊文件"
fsutil hardlink list "D:\CBK-Demo\restore\04-特殊文件\硬链接\三个名字-A.txt"
```

对比表里"说明"一列会写出每个链接的目标、每个硬链接和谁共享数据（H1、H2 两组）。

可以讲的：
- 相对链接还原后**仍是相对的**；绝对链接和 junction 还原后**仍指向原来的位置**——链接里存的就是那串路径，这是正确行为。
- 悬空链接也能原样还原（链接本身不管目标存不存在）。
- 硬链接只存一份内容，还原时用 `CreateHardLinkW` 重建，三个名字仍是同一个文件。
- **管道文件、设备文件**：Windows 的命名管道在 `\\.\pipe\`、设备在 `\\.\` 命名空间，
  不在磁盘目录树里，遍历目录时根本遇不到。这是和 Linux 的平台差异，不是没做。
  其它不认识的重解析点（如 OneDrive 占位符）会记录类型并告警，不会钻进去。

### 4. 元数据：`05-元数据`

先在资源管理器里让老师看两三个文件：右键 → 属性，看"常规"页的修改时间、只读/隐藏；
看"安全"页的权限。（资源管理器要打开"显示隐藏的项目"才看得到隐藏文件。）

| 名字 | 演示什么 |
|---|---|
| `时间-2001年.txt` / `时间-2035年.txt` | 三个时间戳都改成了过去/未来，精确到 7 位小数秒 |
| `属性-只读/隐藏/系统和隐藏/不索引.txt` | 各种属性位 |
| `属性-无存档位.txt` | 连"存档"位都没有，还原后也不能多出来 |
| `只读目录` | 目录本身是只读的 |
| `目录时间-1999年` | 目录的时间戳（必须等目录里的文件都还原完才能设） |
| `权限-阻断继承.txt` | 不继承父目录权限，只有 4 条自定义规则 |
| `权限-额外授权给Guests.txt` | 继承的权限之外多加了一条 |
| `权限目录-阻断继承` | 目录阻断继承，里面的文件从它继承 |
| `属主-SYSTEM.txt` | 属主是 SYSTEM，不是当前用户 |

备份、还原后 `.\scripts\demo\compare_trees.ps1 05`，每一行都应是 √。

可以讲的（最可能被追问）：
- **还原分三趟**：先建所有目录 → 按顺序还原文件并设元数据 → 最后倒序设目录的时间戳和属性。
  因为往目录里写文件会改掉目录的修改时间。
- **只读必须最后设**：先设了只读，后面改时间戳、改权限都会失败。
- 权限存成 SDDL 文本；属主还原需要管理员权限（SeRestorePrivilege），非管理员还原时属主保持为当前用户，并发出告警。

#### 加分演示（时间够的话）

1. **"不恢复元数据"对照**：恢复页勾选"不恢复元数据"，还原到 `D:\CBK-Demo\restore\05-不恢复元数据`，然后

   ```powershell
   .\scripts\demo\compare_trees.ps1 -Source "D:\CBK-Demo\src\05-元数据" -Restored "D:\CBK-Demo\restore\05-不恢复元数据"
   ```

   时间戳、属性、权限都会变成 ×——反过来证明正常还原时确实是程序把它们设回去的。

2. **覆盖策略**：对同一个目标再还原一次，分别选"跳过 / 覆盖 / 重命名"，选重命名会生成 `xxx (1).txt`。

3. **跟随链接**：备份 `04-特殊文件` 时在高级选项里勾"备份链接指向的内容"，还原后链接会变成真实的文件和目录。

## 三、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 生成数据时提示"符号链接只建出 0 / 4 个" | 没用管理员运行。关掉 PowerShell，右键"以管理员身份运行"后重新生成 |
| 还原时告警"建符号链接失败，已降级为空占位" | 同上：GUI 也要从管理员 PowerShell 启动 |
| 对比结果里属主是 × | 还原时不是管理员，属主没法改回 SYSTEM，这是预期的降级行为 |
| 对比提示"还原目录不存在" | 还原目标目录名要和源目录同名，如 `D:\CBK-Demo\restore\04-特殊文件` |
| 第二次还原后对比出现"多出来的" | 上次的还原结果还在、选了"重命名"。先 `make_demo_data.ps1 -CleanRestore` |
| 访问时间显示"N 个不同" | 正常。Windows 读文件时会自动刷新访问时间，备份读源文件时就已经变了，只作参考 |
| 对比表里的时间和文件属性里看到的不一样 | 对比脚本按本机时区显示，精确到 7 位小数；资源管理器只显示到分钟。包里存的是 UTC 原值 |
