# GUI 与加密联调验收

## 本次修复

1. Windows 异常退出码可能大于有符号 32 位整数。Qt 退出信号改用 Python 对象，
   防止 `OverflowError` 使任务状态无法复位。
2. 解密索引的异常转为普通失败；CLI 还有最外层异常处理，返回退出码 2。
   GUI 完成清理后报告错误，允许直接重试。
3. 加密缺少密码在创建输出前被拒绝；xor/vigenere 未初始化密钥时不再越界。
4. xor-cbc 对超过 16 字节的完整 UTF-8 密码计算 SHA-256，取前 16 字节作为密钥块。
   SHA-256 由本项目实现，不使用 CryptoAPI、OpenSSL 或第三方算法实现。
   已用空串、abc、跨填充分块消息和百万字符消息的已知摘要验证。
5. CBC 按块流式处理，保留最后一块以验证 PKCS#7 填充，拒绝截断密文。
6. 备份先写同目录的独占临时文件，完整写入并刷盘后再替换目标。
   失败、取消和发布失败保留原备份。GUI 会清理被强制结束的后台临时文件。
7. 目标目录已存在时核对它确实是目录，避免将普通文件当目录报告成功。
8. 界面默认不加密，也可选择加密算法；加密时检查非空密码和密码确认。
   保留覆盖确认、正确计时和连续任务状态复位，并显示传输阶段的预计剩余时间。
   后台路径按项目位置查找，避免使用开发者机器上的绝对路径。
9. 索引拒绝绝对路径、父目录跳转、驱动器/数据流路径、嵌入空字符与重复条目 ID。
   数据区条目的 ID、类型和路径必须与已验证索引一致，防止损坏数据越出目标目录。

## 兼容范围

容器字段、版本、打包与压缩格式不变。短密码 xor-cbc 的密钥规则保留，
独立构造的旧密文测试继续通过。旧版使用超过 16 字节密码生成的 xor-cbc
归档仍采用截断规则，须使用旧版先恢复后重新备份；不能把此类旧归档解密失败
简单归因于用户记错密码。上一轮使用 CryptoAPI 计算 SHA-256 的长密码归档
与当前项目内实现产生相同密钥。

这三种加密算法是课程中的教学实现；SHA-256 处理长密码不等于把 XOR-CBC
升级为 AES，也不提供认证加密或标准口令派生函数的安全性。

## 测试与边界

- C++：原有单元测试、CBC 任意分块、填充与截断、长密码尾部、摘要已知向量。
- GUI：全部 27 种打包/压缩/加密组合；正确密码、4 类错误/缺少密码、错误后重试。
- 生命周期：启动前取消、实际后台取消和强制终止、超时、异常退出码、旧备份保留。
- 输入：中文空格路径、空文件、空目录、二进制数据、丢失/损坏归档、无效后台配置。
- 规范：仓库 clang-format 脚本、cpplint、Ruff；GUI 回归测试加入 Windows CI。

Qt offscreen 测试验证信号、状态和进程联动，不能替代实际屏幕上的视觉检查。
需要开发者模式或提升权限的符号链接测试，在环境不支持时由原测试显式跳过。

本 PR 增加 `IProgressObserver::OnPhase` 的默认空实现以报告扫描、索引和收尾阶段；
既有实现无需增加 override。该头文件属于组内接口，合并前需由基础模块负责人审阅。
