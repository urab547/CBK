# LZ77 字节流格式

## 接入方式

实现位于 `code/core/src/stages/lz77_stage.*`，工厂为 `Lz77StageFactory`，注册名
`lz77`，类别为 `StageKind::kCompress`。通过现有 `IStage` 接口提供压缩和解压，
不修改公共接口、外层 `.cbk` 容器或引擎。核心匹配和编码逻辑自行实现。

采用 LZ77 的 LZSS 表示方式：字面量与“距离、长度”引用使用标志位区分。
这是项目自定义字节流，不兼容 gzip、ZIP、Deflate 或其他程序的 LZSS 方言。

## 流与块布局

流以 8 字节 ASCII 签名 `CBKLZ001` 开始，随后为若干数据块和一个结束块。
所有多字节整数字段使用小端序。每个块头固定为 13 字节：

| 偏移 | 长度 | 含义 |
|---|---|---|
| 0 | 1 | 模式：0 结束、1 原样、2 LZSS |
| 1 | 4 | 原始字节数 |
| 5 | 4 | 负载字节数，不含块头 |
| 9 | 4 | 原始内容的 IEEE CRC32 |

数据块原始长度为 1–65536 字节；32 位长度仅描述单块，不限制总流长。
结束块全部为零，后面不得追加任何数据。空流为签名加结束块，共 21 字节。
原样模式负载长度必须等于原始长度，内容不变。

LZSS 模式负载必须非空且短于原始内容，否则编码器使用原样模式。
因此最坏空间开销是 21 字节加每个数据块 13 字节。

## LZSS 负载

负载由若干组 token 构成，每组先存储 1 字节标志，随后存储最多 8 个 token。
标志从最低位起对应各 token：

| 标志 | token 长度 | 含义 |
|---|---|---|
| 0 | 1 字节 | 字面量，直接输出 |
| 1 | 3 字节 | 2 字节距离，加 1 字节“长度减 3” |

引用距离范围为 1–32768，且不得超过当前块已输出的字节数；匹配长度为 3–258。
引用以解码器当前输出末尾为基准，逐字节复制，允许源和目标重叠。例如一个字面量 `A`
加距离 1、长度 258 的引用表示 259 个 `A`。

达到块头声明的原始长度时停止读取 token。最后一组没有使用的高位标志必须为零，
负载不得残留字节，引用不得越过原始长度。各块独立，历史窗口在块边界清空。

## 匹配搜索与资源限制

编码器以 3 字节前缀建立 4096 桶哈希链，从最近位置向前搜索 32 KB 窗口。
每次最多检查 64 个候选，每个候选最多比较 258 字节。采用贪心最长匹配，
相同长度优先使用距离较小的候选。候选上限可能降低压缩率，但不影响无损性。

每次输入累计至多 64 KB；满块立即处理，末尾余料由 `Finish()` 输出。
编码器还维护当前块的位置链和编码缓冲，内存为固定块大小的常数倍，并非总计仅
64 KB。解码器按字段接收数据，在读取负载前验证长度，单块输出至多 64 KB。
窗口、索引及缓冲均不随备份总长度增长。

签名、版本、模式、长度、token、引用距离、末组标志、CRC 或流结束检查失败均抛出
`std::runtime_error`。块完整校验后才向下游输出，已输出的前序块不回滚。
CRC 用于检测意外损坏，不提供密码学认证。`Finish()` 后不允许继续输入或再次收尾。

## 使用与验证

CLI 使用 `--compress lz77` 选择本算法；还原时从容器读取算法信息，无需再次指定。
核心接口可设置 `BackupOptions::stages = {"lz77", "huffman"}`，按该顺序压缩，
还原时逆序执行。现有 CLI 的单个压缩选项不表示多个算法，组合能力由核心测试验证。

`code/tests/unit/lz77_stage_test.cpp` 覆盖块边界、任意分段、随机输入、重复内容、
全部字节值、原样回退、独立 token 样例、最大窗口距离、重叠复制、最大匹配长度、
块间历史隔离、截断及恶意引用。引擎测试覆盖三个打包器搭配 LZ77 单独使用和
LZ77→Huffman 串联的备份、列表、校验与还原。

`scripts/test_pack_compress.ps1 -Cbk <cbk.exe路径>` 提供 Windows CLI 回归矩阵：
tar/cpio 分别搭配无压缩、Huffman、LZ77，逐文件比较 SHA256，并核对列表、目录、
只读属性、修改时间、硬链接、空源目录流程及损坏容器拒绝行为。
tar/cpio 的独立工具兼容性验证使用 `scripts/test_tar_compat.ps1`。
矩阵脚本可通过 `-Cipher xor`、`-Cipher vigenere` 或 `-Cipher xor-cbc` 加入加密，
使用固定测试密码经 stdin 传递，验证压缩与加密串联后的完整还原流程。
