# CPIO newc 实现说明

## 接入

实现：`code/core/src/packers/cpio_packer.*`；注册名：`cpio`。
通过 `backup --packer cpio` 选择。接口和 `.cbk` 容器版本保持原值。
核心仅使用标准库及已有 EntryMeta 编码，不调用外部归档程序或第三方归档库。

## 数据布局

采用 SVR4 newc（magic `070701`）：110 字节固定头、13 个八位 ASCII 十六进制字段。
名字包含结尾 NUL；头部加名字、文件内容分别补零至四字节边界。
最后写入零长度的 `TRAILER!!!` 记录。解包要求存在该记录，只允许其后追加零填充。
newc 的 check 字段固定为零；整体完整性由外层容器 CRC32 校验。

实际成员名使用 UTF-8 和 `/` 分隔，并加 `./` 前缀，避免名为 `TRAILER!!!` 的用户文件
被误判为归档结束。内部 inode 按条目序号分配；原始 64 位 EntryMeta id 单独保存。

## 元数据扩展

newc 没有 PAX 式扩展。每个实际成员之前增加普通文件记录
`.__cbk_metadata__/N.bin`，内容为现有 `WriteEntryMeta` 的编码，保存全部 EntryMeta 字段。
辅助记录使用设备号 `(1,0)`，实际成员使用 `(0,0)`，避免 inode 标识混淆。
解包验证辅助记录次序及其与实际成员的名字、类型、长度、链接目标和引用的一致性。
只有实际成员触发条目回调，辅助记录不计入 CBK 索引，也不写入 CBK 还原目录。

`.__cbk_metadata__` 为保留的顶层命名空间，大小写变体同样拒绝；备份此类路径须改名或
选择 tar。外部工具能够列出和提取辅助文件，因此独立解包产物包含该额外目录。
这是一种 CBK 应用层约定，不是 newc 标准扩展。

## 文件类型与硬链接

普通文件、目录、符号链接采用 newc 对应 mode。符号链接目标保存于成员数据区，
不会通过普通文件内容回调输出。目录符号链接和 junction 在标准字段中映射为符号链接，
在辅助记录中保留原始类型。不支持对象在标准字段中表示为空文件，CBK 仍返回 unsupported。

硬链接共用 `(devmajor, devminor, inode)`，内容只随第一个普通文件写入，引用记录大小为零。
现有 IPacker 接口没有原始 nlink，也没有预扫描或头部回填能力。写入端使用 `UINT32_MAX`
作为普通文件候选链接组的 nlink 上限，使读取器能够保留 inode 映射处理后续多个引用。
该值不代表源文件的真实硬链接数量，也不代表归档实际包含的名字数。已验证 CBK 和
CMake 归档工具能够恢复三个名字的内容与链接关系；对严格要求 nlink 等于真实数量的
外部程序不作兼容保证。若后续接口提供链接总数，应改为写入实际值。

无辅助记录的外部 newc 可读取普通文件、目录、符号链接及首个名字携带数据的硬链接组。
数据只出现在组内后续名字的布局明确拒绝，避免输出空文件后丢失后续数据。
外部归档无法提供的 Windows 字段保持默认值；CLI 未增加直接导入独立 `.cpio` 的命令。

## 边界与错误处理

- 单成员数据最多 `4294967295` 字节；超过此限制应选择 tar。
- 实际输入长度必须等于声明长度；大小变化、短写入和非法调用顺序抛出异常。
  当前组员 CLI 的统一异常捕获仍需后续联调，本实现不保证该路径的友好退出码。
- 普通内容直接流式转发，解包使用 64 KiB 缓冲；ID/inode 表随条目数增长。
- 名字及链接目标上限 128 KiB，元数据编码上限 1 MiB 加长度前缀。
- 拒绝非法 UTF-8、上级路径、绝对路径、重复 ID、字段溢出、截断及元数据不一致。
- 仅支持 `070701`，不支持 `070702`、odc、设备或 FIFO，也不承诺所有外部 newc 变体。

## 验证

新增 `code/tests/unit/cpio_packer_test.cpp`，覆盖全部 EntryMeta 字段、各条目类型、
四字节边界、短读、二进制与长名、格式限制、损坏输入以及引擎备份/列表/校验/还原。
本机 MinGW 验证：19 个新增测试通过；全量 206 个测试中 200 个通过，6 个原有符号链接
测试因权限条件跳过。MSVC 未在本机验证，继续使用项目既有 CI 配置。

独立工具验证沿用现有脚本并增加格式参数：

```powershell
.\scripts\test_tar_compat.ps1 -Cbk .\code\build\mingw\bin\cbk.exe -Packer cpio
```

脚本使用 CMake 的归档工具解包 `.cbk` 的原始数据区，对比用户文件 SHA256，
检查额外元数据记录数量，并验证三个硬链接名字共享内容。产物保留于忽略的 build 目录。

格式依据：[Linux 内核 newc 布局说明](https://www.kernel.org/doc/html/latest/driver-api/early-userspace/buffer-format.html)。
